# Аудит Контур 2.0 — 9 октября 2026

## Исправлено

- Сохранение только на одном устройстве заменено общим бюджетом в Supabase; локальный режим и экспорт сохранены.
- Добавлены отдельные логины, автоматическое обновление сессии и привязка кеша к аккаунту и бюджету.
- Защита от потери одновременных правок: атомарная проверка ревизии в базе, объединение независимых изменений, явное разрешение конфликтов, повторная отправка после сетевых ошибок.
- Запрос во время редактирования не затирает более поздние локальные изменения. Открытая для редактирования операция проверяется на изменение с другого устройства.
- Исправлены долгие регулярные операции: расчёт сразу переходит к нужному периоду, без прежнего ограничения в 5000 итераций.
- Для режима дважды в месяц устранён лишний платёж в произвольную дату начала, добавлена корректная обработка коротких месяцев.
- Дефицит начального баланса корректно показывает дату, даже если доход того же дня выводит дневной остаток в плюс.
- Внутренние переводы не уменьшают общий остаток.
- Импорт проверяет уникальность ID, даты, окончания повторений, категории, булевы значения и лимиты; неизвестные поля удаляются.
- Обновления состояния выполняются после проверки; повреждённая исходная локальная копия защищена от перезаписи и доступна для скачивания.
- Добавлены контроль точности итоговых сумм и устойчивая формула кредита для очень маленькой ставки.
- Добавлены поиск и фильтр операций, подписи элементов управления, доступный статус синхронизации, клавиатурный переход к содержимому, адаптация мобильного экрана.
- Исходники отформатированы и разделены на финансовую модель, транспорт, объединение правок и управление синхронизацией.
- Добавлены автоматические проверки и публикация GitHub Pages; на сайт отправляется только явный список публичных файлов.

## Безопасность

- Бюджет и участники не хранятся в Git. Идентификаторы конкретных аккаунтов, реальные почты, пароли, JWT, приватные ключи и пользовательские JSON-копии не добавляются в исходники.
- В браузере только publishable key. Секретные административные ключи не используются приложением.
- На всех таблицах приложения включён RLS. Прямые права у anon/authenticated отозваны. SECURITY DEFINER функции имеют пустой search_path и явную проверку текущего пользователя и членства.
- Пользовательские значения передаются JSON-параметрами; динамического SQL и склеивания запросов нет.
- Пользовательский текст экранируется либо отображается через textContent. CSP запрещает сторонние скрипты, inline-скрипты и произвольные сетевые назначения.
- Приглашение содержит случайный 256-битный код, хранится как SHA-256, истекает через 7 дней и используется один раз. Проверка лимита участников выполняется под блокировкой бюджета.
- Проверка перед публикацией ищет приватные ключи, токены, адреса почты и резервные JSON-файлы. Такая проверка дополняет ручной аудит, но не является доказательством отсутствия любых возможных уязвимостей.

## Выполненные проверки

- 28 регрессионных тестов финансовой модели, включая сохранение автора при нормализации и повторениях.
- 7 тестов объединения изменений, включая удаление и конфликт начального баланса/даты.
- 7 тестов контроллера с конкурентными сохранениями, изменением во время запроса, сетевым отказом, потерей доступа и получением автора от сервера.
- SQL-тесты на реальном проекте Supabase: RLS, отсутствие прямых табличных прав и анонимного доступа, чужой аккаунт, приглашение только владельцем, общий бюджет двух участников, отказ третьему, ввод с попыткой SQL-инъекции, проверка данных, отказ устаревшей ревизии. Все временные данные откатаны.
- Проверка исходников на случайные секреты и личные данные.
- Внешние HTTP-запросы без входа получили 401 при попытке чтения таблицы и RPC. Публичная регистрация отключена в настройках Supabase.
- Проверено безопасное отображение строки с попыткой XSS, форма операции и мобильный экран. Исправлено несовместимое ограничение длины уже созданного пароля на форме входа.
- GitHub Actions успешно выполнил тесты и опубликовал приложение; страница открыта и проверена по HTTPS на GitHub Pages.

## Ограничения

- Синхронизация использует опрос раз в 10 секунд; наличие сети и успешная авторизация обязательны для передачи изменений.
- Офлайн-правки доступны в открытом приложении; отдельного service worker для открытия сайта без сети нет.
- Локальные копии в профиле браузера не зашифрованы. Закрытие вкладки может потребовать нового входа, но не удаляет общий бюджет.
- Нет точной банковской модели кредитных карт и полного журнала фактических долгов; сохраняются описанные в README ограничения финансового прогноза.
- У проекта нет runtime-зависимостей: обновлять библиотечные пакеты приложения не требовалось. Actions используют актуальные поддерживаемые версии из документации GitHub.
