## C–D. Очистка и границы ответственности

В `engine.js` публичные функции продолжают проверять данные; внутренние функции прогноза и текущего баланса принимают уже нормализованные данные. Резерв использует эти внутренние функции без повторных проверок. Даты повторений строятся сразу в нужном месяце или шаге недели; дневные суммы считаются за один обход. Форматировщик денег создаётся один раз.

В `app.js` прогноз хранится вместе с точными входами: объектом состояния, периодом и сценарием. Состояние заменяется при каждой правке; изменение любого входа отменяет повторное использование результата. Проверка сохранения и последующее рисование используют один прогноз. Форматировщики дат и загрузка JSON объединены; поиск неоплаченного повторения использует множество оплаченных дат.

Облачное объединение пропускается только при совпадении ревизии **и полного базового бюджета**, без открытых конфликтов. Метаданные участия обновляются. Иная локальная база, правки во время запроса и новые авторы сервера проходят обычное объединение.

Список публичных файлов вынесен в один контракт для сборки и проверки результата. Новый `scripts/check-build.cjs` проверяет фактический `_site`, хеши HTML и манифеста, версию worker и каждый ресурс офлайн-кэша. Он входит в `npm run build`.

Тестовый помощник `tests/helpers/app.cjs` запускает полный неизменённый `app.js` в VM и вызывает зарегистрированные обработчики. Существующие тесты форм сохранены. Новый набор проверяет прогноз, восстановление, отказ записи, историю, экранирование и темы. DOM в этом помощнике имитируется; реальные экраны проверены отдельно.

Удалены лишняя обёртка `fmt`, повторяющиеся блоки CSS и неиспользуемый селектор старой линии. В worker разрешённые URL строятся один раз. Производственные файлы целиком не удалялись; экспортируемый `monthShift` и совместимость старых сессий сохранены. Порядок списка операций сохранён: коммит `51523c9` явно установил показ более поздних дат первыми; эта совместимость закреплена тестом.
